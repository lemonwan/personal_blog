第 1 站

从 200 行到 1 行：Lambda 的革命

在 Java 8 之前，如果你想传递一段行为（比如一个比较逻辑、一个过滤条件），唯一的办法是写一个匿名内部类：

BeforeJava8.java · 匿名内部类的啰嗦写法
List<String> names = Arrays.asList("Alice", "Bob", "Charlie");

// 需求：按字符串长度排序
Collections.sort(names, new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return Integer.compare(a.length(), b.length());
    }
});

// 需求：过滤出长度 > 3 的名字，然后转大写
List<String> result = new ArrayList<>();
for (String name : names) {
    if (name.length() > 3) {
        result.add(name.toUpperCase());
    }
}

Java 8 引入了 Lambda 表达式，同样的逻辑变成这样：

AfterJava8.java · Lambda + Stream 的简洁写法
List<String> names = Arrays.asList("Alice", "Bob", "Charlie");

// 按长度排序 —— 一行搞定
names.sort((a, b) -> Integer.compare(a.length(), b.length()));

// 过滤 + 转大写 —— Stream 链式操作
List<String> result = names.stream()
    .filter(name -> name.length() > 3)
    .map(String::toUpperCase)
    .collect(Collectors.toList());

从啰嗦的 6 行变成 1 行，从 for 循环变成声明式管道。但面试官想知道的不只是语法糖：

  • Lambda 编译后到底生成了什么？它和匿名内部类在字节码层面有什么区别？
  • 什么是函数式接口？为什么 Lambda 只能对应一个方法？
  • 方法引用（::）的四种形式分别对应什么场景？
  • Lambda 的性能真的比匿名内部类好吗？
第 2 站

Lambda 语法全景与编译原理

Lambda 表达式的语法非常灵活——编译器会根据上下文自动推断参数类型和返回值，允许你省略大量冗余代码：

LambdaSyntax.java · Lambda 各种写法对照
// ① 完整形式：参数类型 + 大括号 + return
Comparator<String> c1 = (String a, String b) -> { return a.length() - b.length(); };

// ② 省略参数类型（编译器从上下文推断）
Comparator<String> c2 = (a, b) -> { return a.length() - b.length(); };

// ③ 省略大括号和 return（单行表达式自动 return）
Comparator<String> c3 = (a, b) -> a.length() - b.length();

// ④ 单参数可省略括号
Consumer<String> printer = s -> System.out.println(s);

// ⑤ 无参数
Runnable task = () -> System.out.println("Hello!");

// ⑥ 多行逻辑必须加大括号
Consumer<String> logger = msg -> {
    String upper = msg.toUpperCase();
    System.out.println("[LOG] " + upper);
};
invokedynamic 是什么？为什么 Lambda 选择它？

invokedynamic 是 Java 7 引入的字节码指令，最初是为了支持动态语言（如 JRuby、Groovy）。它允许在运行时动态决定方法调用的目标。

Lambda 使用 invokedynamic 的好处是：把实现策略的决策推迟到运行时。JVM 的 LambdaMetafactory 在首次调用时生成实现类（基于 ASM 字节码生成），后续调用直接复用。相比匿名内部类在编译时就生成固定 class 文件，这种方式更灵活，且未来 JVM 可以切换为更高效的实现策略（如 MethodHandle），而不需要重新编译用户代码。

第 3 站

函数式接口：Lambda 的"类型"

Lambda 表达式本身没有类型——它必须赋值给一个特定的接口，编译器才能推断参数类型和返回值。这个接口就是函数式接口（Functional Interface）：

函数式接口的定义： 有且仅有一个抽象方法的接口

可以有 default 方法、static 方法、从 Object 继承的方法
但抽象方法只能有一个（SAM: Single Abstract Method）
FunctionalInterface.java · 自定义函数式接口
// @FunctionalInterface 注解：编译期检查，确保只有一个抽象方法
// 不加也能用，但加上是好习惯（防止后人误加第二个抽象方法）
@FunctionalInterface
public interface Calculator {
    int calculate(int a, int b);  // 唯一的抽象方法

    // default 方法不影响函数式接口的判定
    default void print(int result) {
        System.out.println("结果: " + result);
    }
}

// 使用：Lambda 自动匹配 calculate 方法的签名
Calculator add = (a, b) -> a + b;
Calculator mul = (a, b) -> a * b;
add.print(add.calculate(3, 5));  // 输出：结果: 8

除了这四个基础接口，Java 8 还提供了大量特化版本（避免装箱拆箱的性能开销）：

特化接口作用典型场景
ToIntFunction<T>T → int，避免 Integer 装箱list.stream().mapToInt(String::length)
BiFunction<T,U,R>两个输入 T, U → 输出 Rmap.merge(key, val, (a, b) -> a + b)
UnaryOperator<T>T → T（特殊 Function，输入输出同类型）list.replaceAll(String::toUpperCase)
BinaryOperator<T>(T, T) → T（特殊 BiFunction）stream.reduce(0, Integer::sum)
第 4 站

方法引用：Lambda 的终极简化

当 Lambda 体只是简单地调用一个已有方法时，可以用方法引用（::）进一步简化。方法引用有 4 种形式：

MethodReference.java · 四种方法引用形式
/* ─── 形式 1：静态方法引用 ─── */
// ClassName::staticMethod
Function<String, Integer> f1 = s -> Integer.parseInt(s);
Function<String, Integer> f1r = Integer::parseInt;   // ← 方法引用

/* ─── 形式 2：实例方法引用（特定对象）─── */
// instance::method
String str = "hello world";
Supplier<String> f2 = () -> str.toUpperCase();
Supplier<String> f2r = str::toUpperCase;           // ← 方法引用

/* ─── 形式 3：实例方法引用（任意对象）─── */
// ClassName::instanceMethod（第一个参数作为调用者）
Function<String, String> f3 = s -> s.toUpperCase();
Function<String, String> f3r = String::toUpperCase;  // ← 方法引用

/* ─── 形式 4：构造方法引用 ─── */
// ClassName::new
Supplier<ArrayList<String>> f4 = () -> new ArrayList<>();
Supplier<ArrayList<String>> f4r = ArrayList::new;     // ← 构造引用

// 带参构造引用
Function<Integer, ArrayList<String>> f5 = n -> new ArrayList<>(n);
Function<Integer, ArrayList<String>> f5r = ArrayList::new;  // 参数自动匹配
第 5 站

Lambda vs 匿名内部类：不只是语法糖

很多初学者认为 Lambda 只是匿名内部类的语法简化。事实上，两者在编译产物、性能、语义上都有本质区别：

对比维度匿名内部类Lambda 表达式
编译产物生成独立 .class 文件（如 Main$1.class）不生成 .class，用 invokedynamic 指令
实例化方式每次 new 创建新对象无状态 Lambda 复用单例（通过 LambdaMetafactory）
this 语义this 指向匿名类自身this 指向外部类（词法作用域）
变量遮蔽可以定义同名变量遮蔽外部变量不能定义与外部同名的变量
可继承的接口可以实现任意接口（甚至抽象类）只能实现函数式接口
性能类加载 + 对象分配开销首次调用有 Metafactory 开销，后续无状态复用更快
this 语义的区别——面试高频陷阱

在匿名内部类中，this 指向匿名类自身的实例。在 Lambda 中，this 指向定义 Lambda 的外部类实例。

这意味着：如果你在匿名内部类中写 this.toString()，调用的是匿名类的 toString；在 Lambda 中写同样的代码，调用的是外部类的 toString。这个区别在单元测试中经常造成混淆。

第 6 站

实战：Stream + Lambda 常见模式

Lambda 最大的价值在于和 Stream API 的配合，实现声明式的数据处理。以下是几个生产中最常见的模式：

StreamPatterns.java · 常见 Stream + Lambda 模式
List<User> users = getUsers();

// 模式 1：过滤 + 转换 + 收集
List<String> names = users.stream()
    .filter(u -> u.getAge() > 18)            // Predicate
    .map(User::getName)                       // Function
    .sorted()                                  // 自然排序
    .collect(Collectors.toList());

// 模式 2：分组统计
Map<String, Long> countByCity = users.stream()
    .collect(Collectors.groupingBy(
        User::getCity,                         // Function: 分组键
        Collectors.counting()                  // 下游: 计数
    ));

// 模式 3：归约求和
int totalAge = users.stream()
    .mapToInt(User::getAge)                    // 避免 Integer 装箱
    .sum();

// 模式 4：Optional 安全链
String firstAdult = users.stream()
    .filter(u -> u.getAge() >= 18)
    .findFirst()
    .map(User::getName)
    .orElse("无");

// 模式 5：并行流（CPU 密集场景慎用）
long count = users.parallelStream()
    .filter(u -> u.isActive())
    .count();
parallelStream() 什么时候用？什么时候不用？

适合：CPU 密集型计算 + 数据量大（>10000）+ 无共享状态 + 底层是 ArrayList（可高效 split）
不适合：IO 密集型操作、数据量小、LinkedList（split 慢）、有副作用的操作

大多数业务场景下，串行 Stream 已经足够快。过早使用并行流反而可能因为线程切换、ForkJoin 框架开销导致性能下降。
本篇核心要点
  • Lambda 表达式是匿名函数，编译后通过 invokedynamic 指令 + LambdaMetafactory 在运行时生成实现类
  • 函数式接口（SAM 接口）是 Lambda 的类型约束：有且仅有一个抽象方法
  • 四大核心接口：Function（转换）、Consumer（消费）、Predicate（判断）、Supplier（生产）
  • 方法引用是 Lambda 的进一步简化，4 种形式：静态方法、特定实例、任意实例、构造方法
  • Lambda vs 匿名内部类：不生成 .class、invokedynamic、this 指向外部类、无状态可复用
  • 实际开发中 Lambda + Stream API 是处理集合数据的首选方式

21 Lambda 表达式与函数式接口

📖Lambda 表达式基础

Lambda 表达式是 Java 8 引入的最重要的特性，它允许将函数作为方法参数传递，使代码更加简洁。

基本语法：

(参数列表) -> { 方法体 }

语法形式：

  • 无参数：() -> System.out.println("Hello")
  • 单参数（省略括号）：x -> x * 2
  • 多参数：(a, b) -> a + b
  • 带方法体：(x, y) -> { return x > y ? x : y; }
核心理解

Lambda 表达式本质上是一个 函数式接口的匿名实现类的实例。编译器通过类型推断和目标类型（Target Typing）来确定 Lambda 对应的函数式接口。

使用前提：Lambda 表达式必须依赖函数式接口（有且仅有一个抽象方法的接口）。

🔒四大内置函数式接口

Java 8 在 java.util.function 包中提供了四大核心函数式接口：

接口方法签名用途示例
Consumer<T>void accept(T t)消费型，有参无返回值list.forEach(System.out::println)
Supplier<T>T get()供给型，无参有返回值Supplier<Date> s = Date::new
Function<T,R>R apply(T t)函数型，有参有返回值s -> s.length()
Predicate<T>boolean test(T t)断言型，返回 booleans -> s.startsWith("A")

扩展接口：

  • BiFunction<T,U,R> - 两个输入参数
  • UnaryOperator<T> - 输入输出类型相同（Function 的子接口）
  • BinaryOperator<T> - 两个同类型输入，一个输出（BiFunction 的子接口）
  • BiConsumer<T,U> / BiPredicate<T,U>

⚖️Lambda vs 匿名内部类

对比维度Lambda 表达式匿名内部类
底层原理invokedynamic 指令，运行时动态生成编译时生成 Class$N.class 字节码文件
变量捕获只能捕获 effective final 局部变量同样要求变量是 final 或 effective final
this 指向指向外部类对象指向匿名内部类自身对象
字节码体积不生成额外的 class 文件，更轻量每个匿名内部类都会生成一个 .class 文件
使用范围只能用于函数式接口可用于任何接口或抽象类
面试高频陷阱：this 指向

Lambda 中的 this 指向外部类，而匿名内部类中的 this 指向自身实例。这个区别在很多框架的回调场景中可能引发 BUG。

🔬方法引用与构造器引用

方法引用是 Lambda 的语法糖，当 Lambda 体已有现成方法实现时，可以更简洁地引用。

四种形式：

类型语法示例等价 Lambda
静态方法引用类名::静态方法Integer::parseInts -> Integer.parseInt(s)
实例方法引用（特定对象）对象::实例方法System.out::printlnx -> System.out.println(x)
实例方法引用（任意对象）类名::实例方法String::lengths -> s.length()
构造器引用类名::newArrayList::new() -> new ArrayList()
// 示例：各种方法引用List<String> names = Arrays.asList("Alice", "Bob", "Charlie");// 1. 静态方法引用names.sort(String::compareTo);// 2. 实例方法引用（特定对象）names.forEach(System.out::println);// 3. 实例方法引用（任意对象类型）List<Integer> lengths = names.stream().map(String::length).collect(Collectors.toList());

🎤面试高频问题

Q1: Lambda 表达式的编译过程是怎样的？

javac 将 Lambda 编译为 invokedynamic 指令 + 引导方法（Bootstrap Method）-> 运行时 LambdaMetafactory 动态生成实现类 -> 后续调用直接调用已生成的实现（缓存）

Q2: 为什么 Lambda 中使用的局部变量必须是 final 或 effective final？

Lambda 捕获变量时，Java 会将变量拷贝到 Lambda 内部（值拷贝）。如果变量可以修改，拷贝的值和原值将不一致，造成数据不一致问题。因此 Java 强制要求变量是 final 或 effective final（实际不可变），保证安全。

Q3: @FunctionalInterface 注解的作用？

  • 编译检查：确保该接口有且仅有一个抽象方法
  • 文档说明：表明该接口是函数式接口，可用 Lambda 实现
  • 注意：Object 类的 public 方法（如 toString()、equals()）不算抽象方法

Q4: Lambda 与外部变量的作用域？

  • Lambda 中不允许声明与局部变量同名的参数或局部变量
  • Lambda 体中 this 指外部类对象（与匿名内部类不同）
