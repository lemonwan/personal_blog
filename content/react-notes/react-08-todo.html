用「后端思维」先拆需求

第一章学了这么多概念，是时候把它们拧成一股绳了。我们要写一个待办清单（Todo），功能不花哨，但恰好覆盖本章全部知识点：

  • 一个输入框，可以新增待办；
  • 每条待办可以勾选完成、删除；
  • 底部显示剩余未完成数。

用你熟悉的「后端拆接口」套路，先想清楚数据模型和状态，别急着写 UI：

先建模，再写视图（对应先建表，再写接口）
// 一条待办的数据结构
type Todo = {
  id: number;        // 唯一标识（就是 list 的 key）
  text: string;      // 内容
  done: boolean;     // 是否完成
};

// 组件需要的 state
// 1. todos: Todo[]   —— 待办列表
// 2. input: string   —— 输入框当前文字
关键心法

「先定 state、再写 JSX」是最重要的分水岭动作。就像后端「先建表结构、再写 Controller」——state 就是前端的「表结构」。state 定清楚了，界面只是它的投影（还记得第 1 篇的 UI = f(state) 吗？）。

五个动作，逐个攻破

整个组件其实就是 5 个「状态操作」，每个都对应一个知识点：

TodoApp.tsx · 完整实现
import { useState } from "react";

function TodoApp() {
  // ── 状态（先定 state）──
  const [todos, setTodos] = useState([]);
  const [input, setInput] = useState("");
  let nextId = 1;   // 演示用；真实项目建议用自增/时间戳/uuid

  // ── ① 新增：不可变更新，append 新项 ──
  function addTodo() {
    const text = input.trim();
    if (!text) return;              // 空输入拦截（对应后端参数校验）
    setTodos([...todos, { id: nextId++, text, done: false }]);
    setInput("");                   // 清空输入框
  }

  // ── ② 勾选完成：map 置换目标项 ──
  function toggle(id) {
    setTodos(todos.map(t =>
      t.id === id ? { ...t, done: !t.done } : t
    ));
  }

  // ── ③ 删除：filter 过滤目标项 ──
  function remove(id) {
    setTodos(todos.filter(t => t.id !== id));
  }

  // ── ④ 派生值：不要存进 state，直接算 ──
  const remaining = todos.filter(t => !t.done).length;

  // ── ⑤ 视图：状态 → 界面 ──
  return (
    <div className="todo">
      <input
        value={input}
        onChange={e => setInput(e.target.value)}
        placeholder="输入待办…"
      />
      <button onClick={addTodo}>添加</button>

      <ul>
        {todos.map(t => (
          <li key={t.id}>
            <label>
              <input
                type="checkbox"
                checked={t.done}
                onChange={() => toggle(t.id)}
              />
              <span style={{ textDecoration: t.done ? "line-through" : "none" }}>
                {t.text}
              </span>
            </label>
            <button onClick={() => remove(t.id)}>删除</button>
          </li>
        ))}
      </ul>

      <p>剩余 {remaining} 项</p>
    </div>
  );
}

这段代码里藏着的「第一章全部精华」

把它和前面 7 篇一一对应，你会看到每一篇都不是白学的：

代码位置对应知识点来源章节
return (<div>...</div>)声明式：只写「状态 → 界面」的映射第 1 篇
<input value={input} onChange=...>JSX：{} 插值、驼峰属性、受控组件第 2 篇
function TodoApp() / 无任何 props组件：一个函数第 3 篇
useState + [...todos, x] 不可变更新State：不直接 mutate，返回新数组第 4 篇
remaining = todos.filter(...)派生值不存 state（渲染模型的「纯函数」思想）第 5 篇
onChange={() => toggle(t.id)} 箭头函数传参事件：传函数引用/箭头包装第 6 篇
key={t.id}列表 + key：稳定唯一标识第 7 篇
有没有发现一个「后遗症」：let nextId = 1 写在组件函数里，每次重渲染都会被重置，所以 id 可能重复。这是我这句「演示用」注释在回避的问题——真实项目里，id 应该来自后端数据库、Date.now()、或 crypto.randomUUID()。发现问题、意识到边界，正是后端工程师「抠细节」的好习惯。

给自己留三道「课后题」

把这个 Todo 组件在你自己的项目里跑起来，然后依次完成三个小目标：

  1. 加「全部完成」按钮：一键把所有 done 设为 true（练 map 批量置换）；
  2. 加「编辑」功能：双击待办文字变成输入框，回车保存（练「受控组件 + 局部状态」）；
  3. 拆成子组件：把 TodoItem 抽出来，通过 props 接收 todo 和数据回调（练组合 + 单向数据流 + 状态提升，正好接上第 2 卷）。

第一章总结

你已经完成了从「后端思维」到「React 心智」的第一次完整跨越：

  • 声明式：UI = f(state)；
  • JSX：HTML 的外壳、JavaScript 的骨；
  • 组件 + Props：函数 + 不可变单向参数；
  • State：组件字段，不可变更新；
  • 渲染模型：虚拟 DOM 三阶段 diff；
  • 事件 + 列表 key：委托分发 + 稳定身份。

这些就是 React 的「地基」。第 2 卷开始，我们进入真正让 React 强大的部分——Hooks 与状态管理。
