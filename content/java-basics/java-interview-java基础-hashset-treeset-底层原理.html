第 1 站

从一道面试题开始

大厂面试中，集合框架是必考模块，而 HashSet 和 TreeSet 经常被拿来做对比考察：

"HashSet 是如何保证元素不重复的？TreeSet 又是如何实现自动排序的？两者底层分别是什么数据结构？" —— 面试官通过这一个问题，就能判断你对 Java 集合框架的理解深度。

很多同学的回答停留在"HashSet 基于 HashMap，TreeSet 基于 TreeMap"就说不下去了。但面试官想听到的是：

  • HashSet 的 add() 方法内部到底做了什么？为什么 value 是一个固定的 PRESENT 对象？
  • TreeSet 的红黑树是怎么维持有序的？插入后旋转的过程是怎样的？
  • 为什么重写 equals() 就必须重写 hashCode()？不遵守会出什么 bug？
  • TreeSet 不允许插入 null，而 HashSet 允许一个 null——底层原因是什么？

带着这些问题，我们从 HashSet 的源码开始，逐层拆解。

第 2 站

HashSet 底层：披着 Set 外衣的 HashMap

HashSet 的源码非常简短——整个类只有不到 300 行。因为它本质上就是一个 HashMap 的包装器。所有元素都作为 HashMap 的 key 存储，而 value 则统一指向一个静态常量对象：

HashSet.java · JDK 1.8 核心字段
public class HashSet<E> extends AbstractSet<E>
    implements Set<E>, Cloneable, Serializable {

    // 底层存储：一个 HashMap，key 是元素，value 统一用 PRESENT
    private transient HashMap<E, Object> map;

    // 所有元素共享的"假 value"——只为了占位
    private static final Object PRESENT = new Object();

    // 构造方法：初始化 HashMap
    public HashSet() {
        map = new HashMap<>();
    }

    // 带初始容量的构造方法——推荐！避免扩容开销
    public HashSet(int initialCapacity) {
        map = new HashMap<>(initialCapacity);
    }
}

理解了底层结构之后，再来看 HashSet 最核心的三个方法，就非常清晰了：

HashSet.java · 核心方法实现
// add：如果 key 已存在，put 返回旧 value（非 null），则 add 返回 false
public boolean add(E e) {
    return map.put(e, PRESENT) == null;
}

// remove：直接调用 HashMap 的 remove
public boolean remove(Object o) {
    return map.remove(o) == PRESENT;
}

// contains：直接调用 HashMap 的 containsKey
public boolean contains(Object o) {
    return map.containsKey(o);
}
为什么 value 要用一个固定的 PRESENT 对象？

因为 HashSet 只关心"元素是否存在"，不需要存 value。但如果 value 设为 null，add() 方法中 map.put(e, PRESENT) == null 的判断就会失效——无法区分"key 不存在"和"value 本身就是 null"。

所以 JDK 设计者用了一个静态 final 的 Object 实例作为所有 entry 的 value，既节省内存（所有 entry 共享同一个对象引用），又能让 add() 的返回值逻辑正确。

第 3 站

TreeSet 底层：红黑树维持的有序集合

如果说 HashSet 是"无序去重"，那 TreeSet 就是"有序去重"。它的底层同样是一个包装器——基于 TreeMap（NavigableMap 的实现类）。

TreeSet.java · JDK 1.8 核心字段
public class TreeSet<E> extends AbstractSet<E>
    implements NavigableSet<E>, Cloneable, Serializable {

    // 底层存储：一个 TreeMap
    private transient NavigableMap<E, Object> m;

    // 同样是占位 value（和 HashSet 的 PRESENT 类似）
    private static final Object PRESENT = new Object();

    // 默认构造：使用自然排序（元素必须实现 Comparable）
    public TreeSet() {
        this(new TreeMap<>());
    }

    // 自定义比较器构造
    public TreeSet(Comparator<? super E> comparator) {
        this(new TreeMap<>(comparator));
    }
}

TreeMap 的底层是一棵红黑树（Red-Black Tree），这是一种自平衡的二叉查找树。它保证每次插入、删除、查找的时间复杂度都是 O(log n)。

TreeSet 的核心操作都委托给了 TreeMap：

TreeSet.java · 核心方法实现
// add：委托给 TreeMap.put()
public boolean add(E e) {
    return m.put(e, PRESENT) == null;
}

// TreeSet 独有的有序操作方法（TreeSet 有而 HashSet 没有）
public E first()              { return m.firstKey(); }
public E last()               { return m.lastKey(); }
public E lower(E e)           { return m.lowerKey(e); }    // 小于 e 的最大元素
public E higher(E e)          { return m.higherKey(e); }   // 大于 e 的最小元素
public E ceiling(E e)         { return m.ceilingKey(e); }  // 大于等于 e 的最小元素
public E floor(E e)           { return m.floorKey(e); }    // 小于等于 e 的最大元素
public SortedSet<E> subSet(E from, E to)  { /* 范围查询 */ }
为什么 TreeSet 不允许插入 null？

TreeSet 需要对元素进行比较排序。当插入 null 时，TreeMap 在比较阶段会调用 null.compareTo(...) 或 comparator.compare(null, ...)，直接抛出 NullPointerException。

而 HashSet 只依赖 hashCode() 和 equals()，null 的 hashCode 被特殊处理为 0，所以 HashSet 允许一个 null 元素。

第 4 站

equals 与 hashCode 的契约：最容易踩的坑

HashSet（以及 HashMap）的去重机制依赖两个方法的协作：equals() 和 hashCode()。Java 规范要求：如果两个对象 equals 相等，它们的 hashCode 必须相同。反过来不要求。

来看一个经典的反面教材——只重写 equals 不重写 hashCode会发生什么：

BugDemo.java · 只重写 equals 的后果
class User {
    String name;
    int age;

    User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // 只重写了 equals，没有重写 hashCode
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof User)) return false;
        User u = (User) o;
        return name.equals(u.name) && age == u.age;
    }
    // ⚠️ 没有 hashCode()！使用 Object 默认实现（基于内存地址）
}

// 测试：
HashSet<User> set = new HashSet<>();
set.add(new User("Alice", 25));
set.add(new User("Alice", 25));  // 期望被去重

System.out.println(set.size());
// 实际输出：2 ← BUG！两个逻辑相同的对象都被放进去了
// 原因：两个对象的 hashCode() 不同 → 落到不同桶 → equals 根本没机会被调用
为什么"重写 equals 就必须重写 hashCode"？

核心原因是 HashSet/HashMap 的判重是两步走的：

第一步：用 hashCode 定位到数组的某个桶（hash & (n-1)）
第二步：在桶内用 equals 逐个比较

如果两个逻辑相等的对象 hashCode 不同，它们会被分配到不同的桶。第一步就把它们分开了，第二步的 equals 比较根本不会发生——于是 HashSet 认为它们是两个不同的元素。

这就是为什么 Java 规范（Object 类注释里明确写了）要求：equals() 返回 true 的两个对象，hashCode() 必须返回相同的值。

反过来：hashCode 相同但 equals 不同的两个对象，HashSet 能正确区分吗？

答案：可以。hashCode 相同只是说明它们落在同一个桶（哈希冲突），进入桶后还会用 equals 逐个比较。只有 equals 也返回 true，才视为重复。所以 hashCode 相同但 equals 不同是允许的——只是会增加桶内链表/树的长度，降低性能。
第 5 站

HashSet vs TreeSet vs LinkedHashSet 选型指南

在实际开发中，除了 HashSet 和 TreeSet，还有一个常用的实现类 LinkedHashSet。下面做一个全面对比：

特性 HashSet LinkedHashSet TreeSet
底层数据结构 HashMap（哈希表） LinkedHashMap（哈希表 + 双向链表） TreeMap（红黑树）
是否有序 无序 插入顺序 自然排序 / 自定义排序
add / remove / contains O(1) 平均 O(1) 平均 O(log n)
是否允许 null 允许 1 个 null 允许 1 个 null 不允许 null（会 NPE）
内存开销 较小 中等（多维护链表） 较大（每个节点约 48 字节）
典型使用场景 去重、快速查找 去重且保持插入顺序 需要排序、范围查询、取 TopK
LinkedHashSet 的底层实现

LinkedHashSet 继承自 HashSet，但构造时创建的是 LinkedHashMap 而非 HashMap。LinkedHashMap 在 HashMap 的基础上，通过双向链表把所有 entry 串起来，从而保持插入顺序。

所以 LinkedHashSet 的性能和 HashSet 基本一致，只是多了维护链表的少量开销。它的典型场景是：需要去重，但又想保持元素添加的先后顺序（比如 LRU 缓存就是基于 LinkedHashMap 实现的）。

第 6 站

面试高频题汇总

Q1: HashSet 如何保证元素不重复？

HashSet 底层是 HashMap。调用 add(e) 时，实际执行 map.put(e, PRESENT)。HashMap 在 put 时先计算 key 的 hashCode 定位桶位置，再用 equals 与桶中已有元素比较。如果找到相同的 key，put 返回旧 value（非 null），add 返回 false（表示未添加）。

Q2: 为什么重写 equals 必须重写 hashCode？

HashSet/HashMap 判重分两步：第一步用 hashCode 定位桶，第二步用 equals 比较。如果两个逻辑相等的对象 hashCode 不同，它们会落入不同桶，equals 不会被调用，导致去重失败。

Q3: TreeSet 如何实现排序？

TreeSet 底层是 TreeMap，基于红黑树实现。插入元素时通过 Comparable.compareTo() 或 Comparator.compare() 在树中定位，维持二叉搜索树的有序性。中序遍历即为升序序列。

Q4: HashSet 是线程安全的吗？

不是。HashSet 底层是 HashMap，而 HashMap 不是线程安全的。多线程环境下需要使用 Collections.synchronizedSet() 包装，或者使用 ConcurrentHashMap.newKeySet()。

本篇核心要点
  • HashSet = HashMap 的 key 集合 + 固定 value（PRESENT），去重靠 hashCode + equals
  • TreeSet = TreeMap 的 key 集合 + 固定 value（PRESENT），排序靠红黑树 + Comparable/Comparator
  • LinkedHashSet = LinkedHashMap 的 key 集合，保持插入顺序
  • equals 与 hashCode 契约：equals 为 true 的两个对象 hashCode 必须相同
  • HashSet 允许 null，TreeSet 不允许 null（因为无法比较排序）
  • 性能：HashSet O(1) > TreeSet O(log n)，但 TreeSet 提供有序操作

Day 14 — HashSet/TreeSet 底层原理

模块：Java基础 · 集合框架
14 HashSet/TreeSet 底层原理

📖HashSet 底层原理

HashSet 底层基于 HashMap 实现。

  • 底层使用 HashMap<Object, Object>，每个元素作为 HashMap 的 key 存储，value 固定为一个 static final Object PRESENT = new Object()
  • 插入元素时，先计算 hash 值，再通过 HashMap 的 put 方法存入
  • 不允许重复元素，因为 HashMap 的 key 不允许重复
  • 不保证元素的迭代顺序（无序集合）

核心方法映射：

  • add(e) → map.put(e, PRESENT)
  • remove(e) → map.remove(e)
  • contains(e) → map.containsKey(e)

🔒TreeSet 底层原理

TreeSet 底层基于 TreeMap 实现，是有序集合。

  • 底层使用 TreeMap<E, Object>，元素作为 TreeMap 的 key 存储
  • 基于 红黑树（自平衡二叉查找树） 实现
  • 元素按照自然顺序排序（实现 Comparable 接口）或自定义 Comparator 排序
  • 支持 ceiling()、floor()、higher()、lower() 等导航方法
  • 不允许重复元素（key 不可重复）

时间复杂度：

  • 插入/删除/查询：O(log n)
  • 遍历（中序遍历）：O(n)，元素按升序排列

⚖️HashSet vs TreeSet 对比

特性HashSetTreeSet
底层数据结构HashMap（哈希表）TreeMap（红黑树）
是否有序无序有序（自然顺序/自定义）
插入/查询时间O(1) 平均O(log n)
是否允许null允许一个null不允许null
排序支持不支持支持（Comparable/Comparator）
使用场景去重、快速查找需要排序、范围查询

🎤面试常考问题

Q: HashSet 如何保证元素不重复？

A: 依赖 equals() 和 hashCode() 方法。插入时先比较 hashCode，相同再比较 equals。必须同时重写这两个方法。

Q: 为什么重写 equals 必须重写 hashCode？

A: HashMap/HashSet 先用 hashCode 定位桶位置，再用 equals 比较内容。如果只重写 equals 不重写 hashCode，两个"相等"的对象可能有不同 hashCode，导致 HashSet 认为它们是不同的元素。

Q: TreeSet 如何实现排序？

A: 通过 Comparable 接口的 compareTo() 或 Comparator 的 compare() 方法，在红黑树插入时进行比较定位。
