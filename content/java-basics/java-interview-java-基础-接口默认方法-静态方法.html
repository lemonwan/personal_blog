第 1 站

Java 8 之前的接口：纯粹的契约

在 Java 8 之前，接口的定义极其简单——只能包含常量和抽象方法。它是一个纯粹的契约：你告诉我"做什么"，但不告诉我"怎么做"。

BeforeJava8.java - 传统接口的限制
// Java 7 及之前：接口只能有抽象方法和常量
public interface MyCollection<E> {
    // 常量（隐式 public static final）
    int MAX_SIZE = 1000;

    // 抽象方法（隐式 public abstract）
    void add(E element);
    boolean remove(E element);
    int size();
}

// 问题：如果 Collection 接口要新增一个 forEach 方法？
// 答：所有实现类（ArrayList、HashMap、LinkedList...）全部编译失败！

这就是 Java 8 之前接口面临的核心困境：

"接口一旦发布，就无法演进"——这被称为接口的冻结问题

Java 标准库的 Collection 接口被数百万个类实现。如果要在 Java 8 中给 Collection 加一个 stream() 方法或 forEach() 方法，所有现有的实现类——包括第三方库中的——都会在升级 JDK 后编译失败。这在生态庞大的 Java 世界中是不可接受的。

Java 设计者面前有三条路：

  • 选项 A：不升级接口 → 放弃函数式编程能力
  • 选项 B：强制所有实现类适配 → 生态灾难
  • 选项 C：允许接口有默认实现 → 这就是 default 方法
第 2 站

default 方法：接口进化的钥匙

Java 8 引入了 default 关键字，允许在接口中定义带有方法体的默认实现。实现类可以选择继承默认实现，也可以覆写。

DefaultMethodDemo.java - default 方法的语法与使用
public interface Greeting {
    // 抽象方法 —— 实现类必须实现
    String getName();

    // 默认方法 —— 提供默认实现，实现类可选覆写
    default String greet() {
        return "Hello, " + getName() + "!";
    }

    // 另一个默认方法，可以调用其他方法
    default String greetFormal() {
        return "Dear " + getName() + ", welcome.";
    }
}

// 实现类 A：继承默认实现
public class EnglishGreeting implements Greeting {
    public String getName() { return "Alice"; }
    // greet() 和 greetFormal() 自动继承默认实现
}

// 实现类 B：覆写默认方法
public class ChineseGreeting implements Greeting {
    public String getName() { return "张三"; }

    @Override
    public String greet() {
        return "你好，" + getName() + "！";
    }
}

Java 8 标准库中大量使用了 default 方法。最经典的例子是 Collection 接口：

CollectionDefaults.java - Java 8 给 Collection 接口新增的 default 方法
public interface Collection<E> {
    // ... 原有的抽象方法 ...

    // Java 8 新增 —— 全部是 default 方法！
    default Stream<E> stream() {
        return StreamSupport.stream(spliterator(), false);
    }

    default void forEach(Consumer<? super E> action) {
        for (E e : this) {
            action.accept(e);
        }
    }

    default boolean removeIf(Predicate<? super E> filter) {
        Iterator<E> it = iterator();
        while (it.hasNext()) {
            if (filter.test(it.next())) { it.remove(); return true; }
        }
        return false;
    }
}
default 方法的核心价值：
在不破坏已有实现类的前提下，给接口新增方法。

这是 Java 8 引入 Lambda + Stream 的基础设施——没有 default 方法，stream()、forEach()、removeIf() 都无法加到 Collection 接口中。
第 3 站

钻石冲突：多接口的 default 方法碰撞

Java 的类只能单继承，但一个类可以实现多个接口。当两个接口都有同名的 default 方法时，就产生了"钻石问题"。Java 定义了三条明确的优先级规则：

DiamondProblem.java - 三条规则的完整演示
/* ─── 规则 1：类优先于接口 ─── */
interface Greetable {
    default String hello() { return "Hi from interface"; }
}
class Base {
    public String hello() { return "Hi from class"; }
}
class Child extends Base implements Greetable {}
// new Child().hello() → "Hi from class"  (类优先)

/* ─── 规则 2：子接口优先于父接口 ─── */
interface Animal {
    default String speak() { return "..."; }
}
interface Dog extends Animal {
    default String speak() { return "Woof!"; }
}
class Puppy implements Dog {}
// new Puppy().speak() → "Woof!"  (Dog 比 Animal 更具体)

/* ─── 规则 3：平级冲突 → 必须显式选择 ─── */
interface A { default void log() { System.out.println("A"); } }
interface B { default void log() { System.out.println("B"); } }

class MyService implements A, B {
    // 编译器报错！必须覆写并显式选择
    @Override
    public void log() {
        A.super.log();  // 显式选择 A 的实现
    }
}
为什么"类优先于接口"？

这条规则保证了向后兼容。假设你有一个类已经实现了某个接口的方法，后来接口又加了同名的 default 方法——类优先规则确保你原有的代码不会被接口的 default 实现覆盖。

这也是 Java 和 C# 在设计上的重要区别：C# 8.0 也引入了 default interface methods，但选择了不同的解析策略。

第 4 站

接口静态方法：把工具方法放回接口

Java 8 还允许在接口中定义 static 方法。以前这些工具方法只能放在单独的 XxxUtils 类中（如 Collections、Arrays），现在可以直接放在接口里。

StaticMethodDemo.java - 接口静态方法的使用
public interface Validator<T> {
    boolean isValid(T value);

    // 静态方法：通过接口名直接调用
    static <T> Validator<T> always() {
        return value -> true;
    }

    static <T> Validator<T> notNull() {
        return Objects::nonNull;
    }
}

// 使用：不需要单独的 ValidatorUtils 类
Validator<String> v1 = Validator.always();
Validator<String> v2 = Validator.notNull();

标准库中最经典的静态方法例子是 Comparator 接口：

ComparatorStatics.java - Comparator 接口的静态工厂方法
public interface Comparator<T> {
    int compare(T o1, T o2);

    // 静态工厂方法 —— 以前在 Collections 工具类中
    static <T, U extends Comparable<? super U>>
    Comparator<T> comparing(Function<? super T, ? extends U> keyExtractor) {
        return (a, b) -> keyExtractor.apply(a).compareTo(keyExtractor.apply(b));
    }

    static <T> Comparator<T> naturalOrder() { ... }
    static <T> Comparator<T> reverseOrder() { ... }
}

// 使用：直接通过接口名调用
users.sort(Comparator.comparing(User::getAge));
对比维度default 方法static 方法
可覆写实现类可以覆写不能覆写，不能继承
调用方式通过实例调用通过接口名调用
this 引用有（指向实现类实例）没有（不能访问实例成员）
典型用途向后兼容的方法扩展工厂方法、工具方法
第 5 站

Java 9 私有方法：消除 default 方法中的重复代码

Java 8 的 default 方法解决了接口演进的问题，但引入了一个新痛点：当多个 default 方法有公共逻辑时，代码无法复用——你既不能把它抽到另一个 default 方法（会暴露给实现类），也不能用 private 方法（Java 8 不支持）。

Java 9 解决了这个问题：

PrivateMethodDemo.java - Java 9 接口私有方法
public interface Logger {

    // 公共逻辑：格式化和输出（私有方法，不暴露给实现类）
    private String format(String level, String msg) {
        return String.format("[%s] %s - %s", level, LocalDateTime.now(), msg);
    }

    // 私有 static 方法
    private static void writeToConsole(String formatted) {
        System.out.println(formatted);
    }

    // default 方法复用私有方法
    default void info(String msg) {
        writeToConsole(format("INFO", msg));
    }

    default void warn(String msg) {
        writeToConsole(format("WARN", msg));
    }

    default void error(String msg) {
        writeToConsole(format("ERROR", msg));
    }

    // 唯一的抽象方法
    void write(String formatted);
}
Java 9 接口支持的完整成员类型：
1. 常量（public static final）
2. 抽象方法（public abstract）
3. 默认方法（public default） — Java 8+
4. 静态方法（public static） — Java 8+
5. 私有方法（private） — Java 9+
6. 私有静态方法（private static） — Java 9+
私有方法的本质：接口的"内部实现细节"

私有方法让接口的 default 方法可以复用代码，同时不暴露任何实现细节。实现类看不到也调不了这些私有方法——它们纯粹是接口内部的辅助函数。

这使得接口的设计更加高内聚：公共契约（抽象方法 + default 方法）和内部实现（private 方法）清晰地分离开来。

实战选型与面试要点

InterviewQ.java - 面试高频问题速答
// Q1: 接口可以有方法体吗？
// 答：Java 8 起支持 default 和 static 方法，Java 9 起支持 private 方法

// Q2: 一个类实现多个接口，default 方法冲突了怎么办？
// 答：三条规则——类优先 > 子接口优先 > 平级冲突必须显式 InterfaceA.super.method()

// Q3: default 方法和抽象类有什么区别？
// 答：接口支持多实现但不能有状态（实例字段），抽象类有状态但只能单继承

// Q4: @FunctionalInterface 注解和 default 方法的关系？
// 答：default 方法不影响函数式接口判定，@FunctionalInterface 只看抽象方法数量
//     例如 Predicate 有 test() 抽象方法 + and()/or()/negate() default 方法

// Q5: Java 9 的接口私有方法解决了什么问题？
// 答：解决多个 default 方法之间的代码重复问题，
//     允许抽取公共逻辑而不暴露给实现类
本篇核心要点
  • Java 8 之前：接口只能有抽象方法和常量，一旦发布就无法演进（冻结问题）
  • default 方法（Java 8）：允许接口提供默认实现，实现类可选覆写。核心目的是向后兼容地演进接口
  • 冲突解决三规则：类优先 > 子接口优先 > 平级冲突用 InterfaceA.super.method() 显式选择
  • static 方法（Java 8）：接口的工具方法/工厂方法，通过接口名直接调用，不可覆写
  • private 方法（Java 9）：接口内部的辅助方法，不暴露给实现类，用于消除 default 方法间的重复代码
  • 选型原则：无状态行为扩展用接口 default，有状态用抽象类，纯工具用 static
  • 经典实例：Collection 的 stream()、forEach()；Comparator 的 comparing()
